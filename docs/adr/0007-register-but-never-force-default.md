# 默认播放器只登记，不代写 UserChoice

Windows 8 之后，某个扩展名交给谁打开，最终由 `HKCU\…\FileExts\.<ext>\UserChoice` 裁定，
其中的 ProgId 带一个校验值（算法未公开，与扩展名、用户 SID、时间戳相关）。程序自己写它
属于劫持：系统更新后随机失效，还会被安全软件判成恶意行为。

所以「设为默认播放器」拆成两步：本软件把 ProgID、`Capabilities\FileAssociations`、
`RegisteredApplications` 写进当前用户的 Classes，使这些格式的「打开方式」和默认应用页里
出现本软件；真正的「设为默认」由用户在那里点一次（Win11 上该应用页有一个按钮覆盖全部
已登记类型）。应用只负责登记与跳转。

## 考虑过的选项

**直接写 `UserChoice`**：能做成真正的一键，但要复现未公开的校验值，跨版本随时失效。
用「系统升级后关联莫名消失 + 被安软标记」换「用户少点一次」，不值。

**只登记 `OpenWithProgids`，不写 `Capabilities`**：不必跳转系统设置，但本软件不会出现在
默认应用页，「成为默认播放器」也就无从谈起。

## 后果

- 界面必须承认「点过按钮 ≠ 已经设好」：按钮与确认层说的是「登记并打开系统设置」，
  「登记过」与「已是默认」是两种状态，分开显示。
- 登记范围只含音频类扩展名，视频容器（`avi`、`mkv`、`mp4`、`mov`、`ts` 等）不抢；
  清单以 `format.rs` 的注册类别为唯一来源，不另起一份字面量。
- 只写 `HKCU`，不弹 UAC；机器级登记留给将来的 MSI。
- 不做静默自动设置，也不做轮询或重试去催用户；状态靠读 `FileExts\…\UserChoice` 得出。
- 撤销登记只能由用户点按钮完成——现在没有安装器，也就没有卸载清理这条兜底路径。
- 这是 Windows 专属功能，其它平台隐藏入口，不写空的跨平台抽象。
