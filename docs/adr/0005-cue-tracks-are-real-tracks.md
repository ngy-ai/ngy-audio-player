# CUE 分轨产生独立曲目

整轨 FLAC / APE 配一份 `.cue` 是通用播放器最经典的素材，而现有代码把每个文件
当成一条曲目：一个 55 分钟的整轨就是列表里的一行。

CUE 里的一条 track 就是一个真正的**曲目**，标识为 `(文件路径, 起始时间, 结束时间)`。
它能进列表、进队列、被随机抽到、被单独移除。文件本身只打开一次；同一文件内相邻
曲目连续出队时天然无缝，这正是它和 gapless 相互成就的地方。

## 考虑过的选项

**只把 CUE 当作「整轨 + 章节跳转」的附加视图**：实现便宜，但随机播放永远抽不到
第 7 首，「播完整张专辑」还得靠一套和队列平行的逻辑。

## 后果

- 曲目的标识不再是路径。现有去重键 `path_key` 必须升级成 `(路径, 时间窗)`，
  否则同一整轨里的两首会被判成重复。
- 播放列表的持久化格式必须能表达时间窗，这直接决定了列表文件不能是纯路径列表。
- 元数据只能来自文件级标签，CUE 里的 `TITLE` / `PERFORMER` 优先于文件标签；
  封面只能取文件级那一张。
- 队列里相邻两首来自同一文件时不能重复打开文件，引擎侧要按文件分组预读。
- 进度、时长、seek 全部在时间窗内计算，不是文件内的绝对时间。
