# 列表用私有格式存储，m3u8 只做进出口

`library.txt` 现在只存「列表名 + 路径」，制表符转义，并且**不是原子写**——写到一半
崩掉，整个曲库就没了。CUE 分轨（ADR 0005）又要求条目能带上时间窗，纯路径列表
已经装不下。

内部持久化继续用私有文本格式：条目升级为 `(路径, 起始, 结束)`，加格式版本号，
写入走临时文件 + rename 做原子替换。m3u8 只做**导入导出**：导入时缺时间窗就当作
整轨；导出时同一整轨的多个分轨会合并回一行，并在界面上明说「起止时间不会写进
m3u8」。

## 考虑过的选项

**全面改用 m3u8**：好处是外部工具直接可读。但时间窗只能塞进 `#EXT-X-` 自定义
标签，别的播放器重写一次列表就会把这些标签静默丢掉，而丢失是无声的——用户直到
随机播到整轨才发现。存储格式的可靠性优先于互操作。

## 后果

- 库文件带版本号，将来加字段可以先读老版本再升级，不必让用户重建列表。
- 原子写是「曲库不丢」的底线，与格式选择无关，必须一起做掉。
- 导入导出是有损的，界面必须说明损失了什么，而不是安静地降级。
- 私有格式保持纯文本、一行一条，仍然允许用户手工修改。
