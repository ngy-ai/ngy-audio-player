# 「直接设为默认」作为显式选项，保留登记为默认路径

[ADR 0007](0007-register-but-never-force-default.md) 定下「只登记、不代写 `UserChoice`」。
实际用起来代价比预想大：Windows 11 25H2 的「默认应用 → 某应用」页没有一次性按钮，
65 种格式要一个一个点「选择默认值」；而 Win10 / 早期 Win11 上的「设置默认值」已经没了。
中间路线也验证过：给没有 `UserChoice` 的扩展名写 `HKCU\Software\Classes\.<ext>` 默认 ProgID
（Vista 时代的做法），25H2 仍然弹「选择应用」——这条路已经死了。

所以保留 0007 作为默认行为，另加一条**显式**的快捷方式：用户点确认层里的
「直接设为默认」，程序自己算 `UserChoice` 的 `Hash` 写进注册表。

## 考虑过的选项

**只保留 0007**：零风险，但「默认播放器」在 25H2 上等于一个需要点 65 次的功能。

**调官方 API（`IApplicationAssociationRegistration::SetAppAsDefault`）**：Win8 起系统
不再支持这套接口，调用会成功返回但不改关联——花了时间也换不来一次点击。

**写 `.ext` 默认 ProgID**：已实测无效（见上），连「少点一半」都做不到。

**不加提示、静默直写**：用户不知道自己的默认程序被谁改了，出问题时也无从回溯。
所以它是确认层里的一个独立按钮，文案写明「绕过 Windows 的保护、系统更新后可能失效」。

## 后果

- 需要自己实现 `UserChoice` 的哈希：`ext + SID + ProgId + 时间戳（分钟级）+ 体验字符串`
  走 MD5，再两轮带魔数的 32 位混算，Base64 取 12 字符。**右移是无符号的**，
  写成有符号算术右移会得到一个格式正确、但系统永远不认的值。
- 时间戳只精确到分钟，所以「算哈希」与「写键」必须落在同一分钟：代码在整分前 1 秒内
  会等一下，代价是界面卡最多 1 秒。
- 部分扩展名的 `UserChoice` 键带「拒绝写入」的 ACE。写失败时删掉整条键再重建
  （用户对自己名下这个键有删除权），本机上 65 个里恰好 4 个需要这一步。
- 校验失败时系统不报错，只是让这条记录失效、关联退回「询问用什么打开」。所以界面
  显示的是「读到的实际状态」，而不是「我刚才写成功了」。
- 依赖一段未公开的算法：系统大版本更新后可能失效。失效的表现是「双击又弹选择框」，
  此时回到 ADR 0007 的路径即可，不需要回滚代码。
- 多一个纯 Rust 依赖 `md-5`（本来就在依赖树里），不引入原生依赖。
- 登记（ADR 0007）仍是默认动作，也是直写失败后的退路：直写只写 `UserChoice`，
  ProgID 与「打开方式」登记还是走那一套。
